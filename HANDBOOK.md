## 1. Обзор проекта

Десктопное приложение-калькулятор на Go с полностью китаизированным интерфейсом.
Использует **lxn/walk** для нативного GUI Windows, встроенные ресурсы через `embed.FS`,
и Win32 API для аудио и позиционирования окна.

### 2.2. Критические проблемы 🔴

#### Проблема 1: Отсутствует обработка ошибок Win32 API
```go
func mci执行(命令 string) {
    cmdPtr, _ := syscall.UTF16PtrFromString(命令)  // ошибка игнорируется
    mciSendString.Call(...)  // возвращаемое значение не проверяется
}
```
**Риск:** Паника при длинных строках, или команда не выполняется без уведомления.

#### Проблема 2: Утечка ресурсов
- **MP3 во временной папке**: `os.Remove` вызывается только в `main()` при нормальном выходе.
  При `log.Fatal()` или аварийном закрытии окна — файл остаётся в `%TEMP%`.
- **Canvas/Bitmap**: В `初始化()` создаются `canvas` и `resized` bitmap, но при ошибке
  на этапе `NewBitmapBrush` — canvas уже уничтожен, а resized bitmap не имеет `defer Dispose()`.

#### Проблема 3: Сравнение float на точное равенство
```go
if 运算结果 == float64(int(运算结果)) { ... }
```
**Риск:** Для больших чисел ( > 2^53 ) `int(运算结果)` теряет точность.
Например, `9_007_199_254_740_993.0 == float64(int(...))` даст true, хотя число не целое.

#### Проблема 4: Переопределение `user32` в `main()`
```go
func main() {
    user32 := windows.NewLazySystemDLL("user32.dll")  // Новая переменная!
    user32.NewProc("SetProcessDPIAware").Call()
}
```
Создаётся **новая локальная переменная** `user32`, которая затеняет пакетную `var user32`.
Хотя Win32 DLL кэшируется системой, это запутывает код и дублирует инициализацию.

### 2.3. Средние проблемы 🟠

#### Проблема 5: Одиночный монолитный файл
`main.go` содержит 582 строки с UI-логикой, конвертацией, аудио и Win32 прокладками
в одном пакете `main`. Нет модульности, нет возможности переиспользовать конвертацию
в другом проекте без копирования.

#### Проблема 6: DPI-масштабирование отключено
```go
user32.NewProc("SetProcessDPIAware").Call()
```
На современных мониторах с масштабированием >100% интерфейс будет размытым.
Лучше использовать `SetProcessDPIAwareness` из `Shcore.dll` или embed-манифест с `dpiAware`.

#### Проблема 7: Чистый `unsafe.Pointer` для строк
```go
mciSendString.Call(uintptr(unsafe.Pointer(cmdPtr)), 0, 0, 0)
```
Современный подход — `windows.UTF16PtrToString` / `windows.NewLazyDLL` и типизированные вызовы.

#### Проблема 8: Отсутствие тестов
Нет ни одного `*_test.go` файла. Конвертация чисел — идеальный кандидат для unit-тестов.

## 4. Детальный разбор кода

### 4.1. Конвертация чисел

**Текущая реализация:** Посимвольная — каждый китайский иероглиф — одна цифра.
`一二三` → `123`.

**Ограничение:** Не поддерживает традиционные китайские числительные
(например, `十二` = 12, `三百` = 300). Для калькулятора это ок,
но стоит явно документировать.

**Предложение:** Добавить `// Package chinese implements single-digit Chinese numeral conversion.
// Multi-digit numbers like 十二 (12) are NOT supported — each character maps to one digit.`

### 4.2. Аудио

```go
mci执行(fmt.Sprintf(`open "%s" type mpegvideo alias 音乐`, 短路径))
```
Использует MCI с алиасом "音乐". Возможны конфликты, если несколько экземпляров
калькулятора запущены одновременно. Алиас "音乐" не уникален.

**Исправление:** Использовать уникальный алиас через `uuid` или `os.Getpid()`.

### 4.3. UI-сборка

Вся инициализация UI — в одном методе `初始化()`. Это ~100 строк декларативного кода,
смешанного с императивной настройкой (background image, центрирование, обработчики).

**Предложение:** Разбить `初始化()` на:
- `buildLayout() error` — сборка UI
- `setupBackground() error` — фоновое изображение
- `setupCallbacks()` — привязка событий

### 4.4. Функция `设置全部背景`

Имеет O(n) по children панелей. При переключении *Chairman Mode* вызывается
один раз — это нормально. Но при добавлении новых панелей надо не забыть
обновить этот метод.

**Предложение:** Заменить на рекурсивный обход всех children или подписку
на смену темы через event.

## 6. Безопасность

- **Нет проверки пользовательского ввода на длину** — потенциально можно ввести
  очень длинную строку, хотя калькулятор посимвольный.
- **Предсказуемый временный файл** — `%TEMP%\cp_calc_music.mp3` — другой процесс
  может подменить его. Низкий риск для десктопного приложения.
- **`unsafe` пакет** — используется минимально, только для Win32 вызовов.

---

## 7. Кроссплатформенность

Приложение **Windows-only** по дизайну:
- `lxn/walk` — только Windows (native Win32 API)
- `winmm.dll` — только Windows
- `user32.dll` — только Windows

**Если нужна кроссплатформенность:** заменить walk на Fyne, Gio, или веб-интерфейс.

### Что изменилось в процессе рефакторинга

1. **Пакет `assets/`** — единое место для embed.FS. Файлы `leader.png` и `music.mp3` скопированы туда с коротким именем для mp3.

5. **Тесты** — 6 тестов для конвертации чисел: граничные случаи, NaN, Inf, круглые числа.
6. **Сборка** — бинарник уменьшен флагами `-ldflags="-s -w"`.
